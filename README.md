# Battleship

Landon Holland's semester project for CS 457 (Computer Networks): a two-player Battleship game played in the console over TCP, written in Python. One server and two clients run on separate nodes in a CML multi-subnet topology.

**Status:** Sprint 1, design. The application protocol and the server state machine are specified. There is no game code yet.

## Sprint 1 Deliverables

| Deliverable | What it covers |
| ----------- | -------------- |
| [Protocol Blueprint](docs/protocol_blueprint.md) | The message envelope, all 10 message types with field tables and sample JSON, error codes, board encoding, every way a game can end, message framing with raw wire examples (back-to-back, fragmentation, coalescing) and the receiver algorithm, and connection termination |
| [FSM Specification](docs/fsm_specification.md) | The server state machine as a Mermaid `stateDiagram-v2` diagram, what counts as a lost player, a state table, every edge case and failure path, and turn enforcement |
| [AI Prompts](docs/ai_prompts.md) | The standing system prompt that keeps Claude to the blueprint, and the constrained prompts used for each component |
| [Statement of Work](sow_template_LH.md) | Game rules, scope, concurrency plan, and the CML topology and deployment plan |

The protocol blueprint is the single source of truth. The other documents follow it.

## The Design at a Glance

- **Transport:** TCP on port 5000. The client finds the server as `server.holland.edu` through DNS.
- **Messages:** one JSON object per message, UTF-8, ended by a single newline byte (`0x0A`).
- **Server:** one thread with a `selectors` event loop and non-blocking sockets. It is the only authority on the game: clients keep no game state and only draw what the server sends.
- **Game flow:** both players connect, both place their fleets, then they take turns firing one shot at a time until one fleet is sunk. Every game ends the same way: the server sends `GAME_OVER` to each player it can still reach, closes both connections, and waits for the next two players.

## Checking the Docs

The raw wire example in the protocol blueprint (#6) was generated by a script, not typed by hand. To rebuild it and confirm the blueprint still matches it byte for byte, run this from the repository root (Python 3, standard library only):

```text
python tools/wire_example.py
```

It prints the stream and its byte table, and exits with an error if anything in the blueprint differs.
